# S2C1.3 — Khóa theo phiên trình duyệt + mở khóa offline

> **Failing test:** `specs/S2C1.3-session-key-offline-unlock.test.mjs` — `node specs/S2C1.3-session-key-offline-unlock.test.mjs`
> **Plan + quyết định Q1/Q2:** `specs/ROADMAP-S.md` § "Plan đợt S2C1.2 → S2C1.4".
> **Thay thế:** D5 của S2C1 ("khóa chết theo cửa sổ") và bước verify tay 4 của S2C1
> ("đóng popup mở lại → modal unlock"). Đóng FLAG offline của S2C1.1.

## Vấn đề

1. **UI chính là popup** (`manifest.json` `default_popup: index.html`). Theo D5, DEK chỉ nằm trong
   RAM của cửa sổ → popup đóng mỗi khi mất focus → **mỗi lần bấm icon phải gõ passphrase**.
2. **Service worker không bao giờ có key** → đường đồng bộ nền không mã hóa được (S2C1.4 cần).
3. **Offline không mở khóa được**: row `user_crypto` (salt, `wrapped_dek`, verifier) chỉ lấy từ
   server.

## Thiết kế

`chrome.storage.session` chỉ nằm trong RAM của trình duyệt (không ghi đĩa), mất khi đóng trình
duyệt / reload / update extension, mặc định không lộ cho content script. Repo đã dùng nó cho
refresh token Supabase (`utils/storage.ts` `chromeSessionStorageAdapter`) và khóa bookmark PIN
(`utils/bookmarkSessionKey.ts`). Vì session Supabase cũng ở đó, **mọi trạng thái "đang đăng nhập"
đều có trình duyệt đang mở** → cache trong session là đủ cho offline, không cần đụng đĩa.

| Key session | Nội dung | Ghi khi | Xóa khi |
|---|---|---|---|
| `bbqone_account_crypto_status` | `{userId, row}` (row = null nếu chưa bật) | `refreshStatus` thành công, enable, recovery | logout / mất session / mount khi không ai đăng nhập |
| `bbqone_account_dek` | `{userId, dekId, dekB64, expiresAt}` | unlock / enable / recovery | hết hạn, "Khóa ngay", logout |
| `bbqone_account_dek_extended_until` | mốc hạn đã gia hạn | có thao tác (≤ 1 lần/phút) | cùng lúc với DEK |

Hạn hiệu lực = max(`expiresAt`, `extended_until`). Gia hạn **chỉ ghi key riêng** — chạy đua
với "Khóa ngay" (kể cả ở context khác) cũng không bao giờ ghi lại được entry DEK đã xóa.

## Thay đổi

1. **`src/utils/accountSession.ts` (mới)** — đọc/ghi 3 key trên; `readSessionDek` tự xóa khi hết
   hạn; `touchSessionDek`; `purgeExpiredSessionDek` (alarm `bbqone-account-autolock`);
   `resolveAccountForPush(userId)` (S2C1.4): chưa biết / user khác → `{key:null}`, chưa bật →
   `null`, bật + DEK hợp lệ → `{key, kid}`. **Không đụng `chrome.storage.local`**, không nhắc tới
   service `user_crypto` (giữ ranh giới S2B W3).
2. **`services/userCrypto.service.ts`** — thêm `fetchUserCryptoStatus()` trả `{userId, row}`;
   `fetchUserCryptoRow` gọi lại nó.
3. **`stores/accountCrypto.ts`**:
   - `refreshStatus`: thành công → ghi status vào session; lỗi mạng → dùng bản session
     (`stale = true`); không có bản session → throw như cũ (= chưa biết).
   - `applyStatus`: user / `dek_id` đổi → bỏ key đang cầm.
   - `enable` / `unlock` / recovery → `persistSession` (status + DEK).
   - `restoreFromSession()`: DEK đúng user + đúng `dek_id` → mở khóa không hỏi passphrase.
   - `markActivity()` (gia hạn, ≤ 1 lần/phút), `lockNow()` (persistCache khi còn key → bỏ key →
     xóa DEK session → `hydrateFromCache`), `clearStatus()` xóa luôn session.
4. **`stores/notes.ts` `requireAccountKey`** — `markActivity()` (đang gõ thì không tự khóa).
5. **`pages/App.vue`**:
   - `refreshAccountCryptoStatus`: thử `restoreFromSession()` trước khi mở modal unlock.
   - `refreshStoresFromNetwork`: `!account.fetched || account.stale` → hỏi lại server.
   - Mount: nghe `chrome.storage.onChanged` (session) — DEK bị xóa → `lockAccountNow`; DEK mới →
     restore + `onAccountUnlocked`. Không ai đăng nhập → `clearAccountSession()`.
   - `lockAccountNow`: `flushSave()` (còn key) → `selectNote(null)` → `account.lockNow()`.
6. **`components/layout/SettingsModal.vue`** — nút **Khóa ngay** (emit `lock-account`); i18n
   `account.lockNow`; `account.statusUnlocked` đổi nội dung.
7. **`background.ts`** — alarm `ACCOUNT_AUTOLOCK_ALARM` → `purgeExpiredSessionDek()`.
8. **`SECURITY.md`** — mô tả khóa theo phiên + mở khóa offline.

## KHÔNG đổi

- Không ghi DEK, `K_content` hay row `user_crypto` xuống `chrome.storage.local`.
- Thuật toán, envelope, ceremony, recovery re-wrap.
- `lock()` vẫn chỉ bỏ key trong RAM (logout dùng nó).
