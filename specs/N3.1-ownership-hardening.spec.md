## PHẦN A — SPEC

### Root cause (theo finding)

1. **[High] Ownership chỉ gate 1/3 đường push.** `ensureLocalDataOwnership` chỉ được gọi tại
   `src/App.vue:91` (SIGNED_IN). `runBackgroundAutoSync` (alarm 5' + network-restore,
   `autoSync.service.ts:77-88`) và `runManualSync` (`stores/sync.ts:58-70`) vẫn
   `pushLocalToCloud`/`syncFromCache` **không check owner**. Kịch bản: B login → SIGNED_IN →
   `ensureLocalDataOwnership` đang chạy async → alarm/network-restore/nút sync bắn
   `pushLocalToCloud` TRƯỚC khi purge xong → data A upsert dưới `user_id` B. Hoặc: popup đóng
   ngay sau login trước khi ensure hoàn tất → owner key chưa đổi → alarm 5' của SW push data A.
2. **[High] Context A còn mở khi B login ở context khác.** Session Supabase nằm chung
   `chrome.storage.session` → client của context A giờ mang session B; disk bị purge nhưng
   Pinia A còn nguyên notes của A → `persistCache` (N5 read-merge-write làm dirty rows
   **dễ sống sót hơn**) ghi lại data A xuống đĩa → autoSync đẩy lên account B.
3. **[Medium] Suppress chỉ ẩn Pinia.** `suppressUnexpiredPendingDeletes`
   (`pages/App.vue:112-126`) lọc state nhưng `loadAll()` NGAY TRƯỚC ĐÓ đã `persistCache()` row
   sắp-xóa xuống đĩa → context mới hydrate sẽ hồi sinh note đang chờ undo.
4. **[Medium] `runManualSync` bỏ qua `errors[]`** của `pushLocalToCloud`
   (`stores/sync.ts:60-62`) → partial fail vẫn `markSynced()` — badge "synced" giả còn trên
   nhánh lỗi.
5. **[Low] `folders.ts` persistCache** (`folders.ts:32-34`) chưa qua `safeCacheWrite` — còn
   throw quota (N1 chủ đích bỏ qua, nay vá luôn cho đồng nhất).
6. **[Low — CHẤP NHẬN, KHÔNG SỬA] `supabaseAuthLock` chờ lock vô hạn:** Web Locks tự release
   khi context giữ lock chết → lock "kẹt vĩnh viễn" không xảy ra; trường hợp context sống mà
   fetch treo là rủi ro sẵn có của auth-js. Ghi nhận, không đổi code (tự chế error-type mà
   auth-js không nhận còn rủi ro hơn).

### Thay đổi 1/7 — `src/services/localFirst/dataOwner.service.ts`: thêm guard đọc-nhanh

Đặt sau `ensureLocalDataOwnership` (`:87-125`):

```ts
/**
 * N3.1: guard tại-thời-điểm-push cho MỌI đường push (autoSync alarm, network-restore,
 * manual sync, post-login). true = được phép push local data dưới user này:
 * owner null (anonymous onboarding) hoặc owner === currentUserId.
 */
export async function isPushAllowedFor(currentUserId: string | null): Promise<boolean> {
  if (!currentUserId) return false
  const chunk = await chrome.storage.local.get(BBQ_DATA_OWNER_USER_ID_KEY)
  const owner = (chunk[BBQ_DATA_OWNER_USER_ID_KEY] as string | undefined) ?? null
  return owner === null || owner === currentUserId
}
```

### Edge case BẮT BUỘC giữ

1. **Anonymous onboarding** (owner null) → `isPushAllowedFor` = true → push như cũ.
2. **A→B→A restore-own-stash:** sau khi ensure đổi owner về A, `isPushAllowedFor(A)` = true →
   stash restore được push bình thường.
3. `selfOwnerChange` chỉ chặn reload ở CHÍNH context login; các context khác (kể cả context
   đang mở dashboard-tab của A) PHẢI reload.
4. `syncFromCache` guard đặt SAU `isAuthenticated` (offline → return 0 sớm như cũ, không gọi
   `getCurrentUserId` khi offline).
5. `runManualSync` khi guard chặn: `markError` + return — KHÔNG throw (caller `runAutoSync`
   nuốt throw, nhưng UI badge phải đỏ và không "synced").

### KHÔNG được đổi (chặn over-reach)

- KHÔNG sửa `ensureLocalDataOwnership` (logic stash/purge/restore giữ nguyên).
- KHÔNG thêm dialog/UI mới; reload là cơ chế duy nhất cho stale context.
- KHÔNG đổi `supabaseAuthLock` (finding #6 — accepted risk, đã ghi lý do ở trên).
- KHÔNG gộp thêm batch-push/N9-optimization vào PR này.

### ⚠ FLAG liên đới

- **Cửa sổ mili-giây còn lại (accepted):** giữa lúc `ensureLocalDataOwnership` purge xong và
  event `onChanged` tới context cũ, context cũ có thể kịp 1 lần `persistCache` — nhưng
  server-leak đã bị chặn bởi guard tại-thời-điểm-push (Thay đổi 2+3); rác cache sẽ bị pull
  của B ghi đè (row A dưới session B là clean-absent → merge drop). Không còn đường lên server.
- Reload ở context vừa login (không xảy ra nhờ `selfOwnerChange`) — nếu tương lai refactor
  `runSyncFlow`, giữ nguyên flag này.
