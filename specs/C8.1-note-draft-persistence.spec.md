> `flushSave` đi qua `updateBody` — **network trước, cache sau** — nên khi popup bị hủy thật
> (MV3 popup chết ngay khi mất focus), fetch bị kill và nhánh catch (ghi cache) không kịp chạy.

## PHẦN A — SPEC

### Nguyên tắc

1. Draft là **lưới đỡ ephemeral**, không phải nguồn dữ liệu: `chrome.storage.session` (in-memory,
   sống qua popup close, tự mất khi browser restart — đúng phạm vi ca lỗi popup-kill; browser
   restart đã mất session auth thì draft cũng không còn chỗ áp).
2. **1 slot draft duy nhất** (chỉ một editor active tại một thời điểm; switch body đã có flush
   sẵn tại watch `activeBodyId` — [NoteEditor.vue:144-160](../src/components/notes/NoteEditor.vue)).
3. **KHÔNG ghi draft cho body thuộc secure folder** — draft là plaintext nằm ngoài vòng đời
   JS-memory mà secure design đang giữ. Secure notes chấp nhận giữ nguyên cửa sổ 2s.
4. Draft chỉ cover **content** (đường autosave/flushSave hiện tại chỉ save content — label đi
   đường update trực tiếp, ngoài scope).

### Thay đổi 2/4 — Service mới `src/services/noteDraft.service.ts`

```ts
import { BBQ_NOTE_DRAFT_SESSION_KEY } from '@/constants/storage'

export interface NoteEditorDraft {
  bodyId: string
  noteId: string
  content: string
  /** ISO — thời điểm keystroke cuối (client clock, ms). */
  at: string
}

function isValidDraft(raw: unknown): raw is NoteEditorDraft {
  if (typeof raw !== 'object' || raw === null) return false
  const d = raw as Record<string, unknown>
  return (
    typeof d.bodyId === 'string' && d.bodyId.length > 0
    && typeof d.noteId === 'string'
    && typeof d.content === 'string'
    && typeof d.at === 'string' && d.at.length > 0
  )
}

export async function saveNoteDraft(draft: NoteEditorDraft): Promise<void> {
  try {
    await chrome.storage.session.set({ [BBQ_NOTE_DRAFT_SESSION_KEY]: draft })
  } catch {
    /* best-effort */
  }
}

export async function readNoteDraft(): Promise<NoteEditorDraft | null> {
  try {
    const chunk = await chrome.storage.session.get(BBQ_NOTE_DRAFT_SESSION_KEY)
    const raw = chunk[BBQ_NOTE_DRAFT_SESSION_KEY]
    return isValidDraft(raw) ? raw : null
  } catch {
    return null
  }
}

export async function clearNoteDraft(): Promise<void> {
  try {
    await chrome.storage.session.remove(BBQ_NOTE_DRAFT_SESSION_KEY)
  } catch {
    /* best-effort */
  }
}

/**
 * Chỉ áp draft khi body đích còn tồn tại VÀ draft mới hơn bản trong cache.
 * So sánh ms qua Date là đủ (draft.at và updated_at local đều ms; updated_at server µs
 * chỉ chênh dưới-ms — draft thật sự mới hơn thì luôn cách xa hơn thế).
 */
export function shouldApplyDraft(
  draft: NoteEditorDraft,
  body: { id: string; updated_at: string } | null | undefined,
): boolean {
  if (!body || body.id !== draft.bodyId) return false
  return new Date(draft.at).getTime() > new Date(body.updated_at).getTime()
}
```

```ts
let draftTimer: ReturnType<typeof setTimeout> | null = null

function isSecureActiveNote(): boolean {
  const nid = notesStore.activeNoteId
  const note = nid ? notesStore.notes.find((n) => n.id === nid) : null
  const folder = note?.folder_id
    ? foldersStore.folders.find((f) => f.id === note.folder_id)
    : null
  return !!folder?.is_secure
}

/** Throttle ~300ms: draft luôn tươi hơn debounce-save 2s, đủ rẻ để chạy mỗi keystroke. */
function scheduleDraftWrite(): void {
  if (draftTimer !== null) return
  draftTimer = setTimeout(() => {
    draftTimer = null
    const id = notesStore.activeBodyId
    const ed = editor.value
    if (!id || !ed || !notesStore.isDirty) return
    if (isSecureActiveNote()) return // plaintext secure không ra khỏi JS memory
    void saveNoteDraft({
      bodyId: id,
      noteId: notesStore.activeNoteId ?? '',
      content: ed.getHTML(),
      at: new Date().toISOString(),
    })
  }, 300)
}
```

**4b. Hàm khôi phục** (đặt cạnh `maybeShowConflictBackups`):

```ts
/** Popup bị kill trước khi debounce-save kịp chạy → áp lại draft từ session storage. */
async function maybeRestoreNoteDraft(): Promise<void> {
  const draft = await readNoteDraft()
  if (!draft) return
  const body = notes.bodies.find((b) => b.id === draft.bodyId)
  if (!shouldApplyDraft(draft, body)) {
    await clearNoteDraft() // draft cũ hơn cache / body đã xóa → bỏ
    return
  }
  try {
    await notes.updateBody(draft.bodyId, { content: draft.content })
    await clearNoteDraft()
  } catch (e) {
    console.error('[BBQOne] Note draft restore failed:', e)
    /* giữ draft — thử lại lần mở popup sau */
  }
}
```

`await` trước pull là chủ đích: online → `updateBody` push xong mới pull (row sạch, không đua);
offline → fallback ghi cache dirty → C1 merge-guard bảo vệ khi mạng về. `updateBody` đi qua đúng

### Cái KHÔNG được đổi

- **KHÔNG** đổi thứ tự network/cache trong `notes.updateBody` (hướng đã loại — xem đầu spec).
- **KHÔNG** đụng debounce 2000ms của `scheduleSave`, pagehide/visibilitychange flush của C8,
  logic secure decrypt/encrypt, sync loop.
- Không dependency mới, không migration, không đổi manifest (permission `storage` đã có,
  `chrome.storage.session` dùng chung permission đó).

### ⚠ FLAG liên đới

1. Draft ghi ở popup, đọc ở popup — SW không đụng key này. Không có race SW.
2. Nếu user gõ ở máy A (popup kill, draft giữ), rồi sửa cùng body trên máy B mới hơn: lần mở
   popup A sau đó, `shouldApplyDraft` so draft.at với `updated_at` bản pull về — draft cũ hơn →
   bỏ. Draft mới hơn → áp qua `updateBody` (interactive) → nếu server đã đổi, C9.1 retry-once
   xử lý; thua thật thì SyncConflictError → draft giữ lại, không mất.
3. Restore chạy trước pull nên so sánh với cache (có thể stale hơn server). Trường hợp xấu nhất:
   áp draft lên bản cache cũ → push → server từ chối/ghi tùy baseline — đều đi qua cơ chế C9.1
   đã có, không tạo đường mất data mới.
